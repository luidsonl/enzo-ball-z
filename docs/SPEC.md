# EnzoBallZ — MVP Specification

> This document describes the game rules and balancing targets. Numeric values
> are starting points; balancing may change without changing the architecture.
>
> **Audit note (2026):** The core and client have been migrated to the action
> slots / modular skills model. Sections below distinguish **implemented**
> behavior from **planned/partial** behavior where relevant.

## 1. Goal

A 2D platformer in the style of Mario, written in Rust and compiled to
WebAssembly. Players control a playable character (Enzo or Valentina), run,
jump, fight, and farm aura by alternating the `6` and `7` keys. Aura is mana
for aura-based skills such as **Mogging**. Enemies grant XP; XP levels up the
character and grants points to distribute into Speed, Strength, Health, Aura,
and Ego (intelligence). Players can customize character appearance (skin, hair,
face, and outfit colors/slots) through stable visual profile IDs.

## 2. Scope

- One level with horizontal scrolling and a tilemap.
- One player in the MVP, with a core ready for N players.
- Playable character selection: **Enzo** or **Valentina** (implemented as
  separate playable entities; Valentina can have different animations/visuals).
- Character customization via stable visual profile IDs (skin, hair style/color,
  face, outfit slots) — data model functional; full UI/layer compositor pending.
- Mario-style movement, including running via double-tap.
- Aura farming with alternating `6`/`7`, combo, and slowdown.
- 3-hit physical combo.
- One special attack: **Mogging** (instant horizontal projectile).
- One patrolling enemy type.
- XP, level-up, points, and five attributes.
- Health, aura, death with respawn, and victory by touching the flag.
- Start menu with three save slots and language options.
- Fixed HUD with draggable status/inventory/equipment/skills windows opened by
  dots.
- UI in Brazilian Portuguese and English, with a persisted choice.
- Local auto-save of progression per slot.
- Original pixel-art sprites generated by script.
- **Implemented (core/client adaptation):** 4 generic action slots, modular
  skills, loadout in core/save/snapshot, and generic skill dispatch.

## 3. Non-goals (current MVP scope)

- Network multiplayer, server, matchmaking, authentication.
- Local co-op.
- More than one level, bosses, shops, and map item pickups beyond what exists.
- Audio.
- Graphics options.
- Third-party assets (including Dragon Ball or Mario characters/names/art).

## 4. Game loop

```text
Explore and fight enemies
        │
        ├─ physical attack (slot skill, default J) ──▶ free damage, short range
        │
        ├─ farm aura (6/7) ─────────────────────────▶ fills the bar, but slows Enzo
        │
        └─ Mogging (slot skill, default K) ─────────▶ spends aura, ranged damage
                                  │
                                  ▼
                         enemy dies ──▶ XP
                                  │
                                  ▼
                         level-up ──▶ +1 point
                                  │
                                  ▼
                 distribute: Speed / Strength / Health / Aura
                                  │
                                  ▼
                         reach the flag = victory
```

## 5. Controls

### 5.1 Implemented defaults (keyboard)

| Action | Keys | Notes |
| --- | --- | --- |
| Move | `A`/`D` or `←`/`→` | Digital horizontal axis |
| Up / fly intent | `W`/`S` context: `W` or `↑` | Vertical intent (`move_y = -1`), used by fly/vertical mechanics |
| Jump (also) | `W` or `↑` | Also triggers slot 1 jump on press (quality-of-life mapping) |
| Skill slot 1 | `Space` | Default: Jump |
| Skill slot 2 | `Left Shift` / `Right Shift` | Default: Dash |
| Skill slot 3 | `J` | Default: Melee (3-hit combo) |
| Skill slot 4 | `K` | Default: Mogging |
| Farm aura (SixSeven) | `6` and `7` | Alternation required; **outside** skill slots |
| Distribute point | `1` `2` `3` `4` or click | In the status/level-up UI |
| Confirm | `Enter` or click | Confirms level-up/UI actions where supported |
| Restart level | `R` or click | On death/victory flows |
| Open menu | `Esc` | Save and return to the start menu |
| Menu/HUD navigation | mouse | Edge-triggered click |

**Movement details:** double-tap in the same direction activates running; holding
the direction keeps running. Up (`W`/`↑`) currently serves both as vertical/fly
intent and as a jump press trigger for slot 1.

### 5.2 Action slots and loadout (implemented in core; UI editing partial)

- 4 generic slots (`ActionSlot::Slot1..Slot4`). Any available `SkillId` can
  occupy any slot; the same skill must never occupy two slots.
- `PlayerCommand` carries `move_x`, `move_y`, `slots[4]` (`pressed`/`held`),
  `sixseven`, and UI/meta fields — not fixed `jump`/`dash`/`melee`/`mogging`
  fields.
- `slot → SkillId` loadout lives in `enzo-core`, persists in saves, and appears
  in snapshots. `Loadout::assign` swaps/moves (no duplicates); saves are
  sanitized on load.
- Default loadout: Slot 1 Jump, Slot 2 Dash, Slot 3 Melee, Slot 4 Mogging.
- Skills declare requirements (entity type, level, attributes, equipment tags)
  and have icon/asset metadata.
- **Partial/planned:** full in-game loadout editing UI, loadout bridge actions,
  configurable keybinding persistence/remap UI, and touch controls.

## 6. Movement

- Ground: acceleration `1800 px/s²`, deceleration `2200 px/s²`.
- Walk speed: `220 px/s`; run speed: `340 px/s`.
- Air: acceleration `1200 px/s²`, no friction.
- Jump: impulse `-560 px/s`; gravity `1800 px/s²`; max fall `900 px/s`.
- **Coyote time:** `0.10 s` after leaving a platform.
- **Jump buffer:** `0.12 s` before touching the ground.
- **Double-tap:** two presses in the same direction within `0.25 s` start
  running. Releasing the direction, reversing, or stopping cancels running.
- Variable jump: releasing the jump input early cuts ascent.
- **Dash (skill):** horizontal impulse `520 px/s` for `0.14 s`, cooldown `0.7 s`,
  no aura cost. Uses held direction or current facing; can be used on ground or
  in air (subject to skill rules).
- **Fly (skill):** implemented as a slotted/available skill with hold behavior
  driven by `move_y` (not granted by default to the MVP player in the base
  design; availability depends on requirements/loadout).
- AABB collision against tiles; resolve X, then Y.

Walking and SixSeven are mechanics outside skill slots. Jump, Dash, Fly, Melee,
Mogging, Nutella Shot, and Shout are skill modules with requirements and typed
state.

## 7. Aura and SixSeven

- Base aura bar: `100`.
- **SixSeven** is the aura-farming mechanic: alternating `6 → 7 → 6 → 7` counts
  as a hit. It is **not** a skill slot action.
- Repeating the same key (e.g., `6, 6`) resets the combo and generates no aura.
- Each hit generates `2` aura × multiplier.
- Multiplier: `1 + 0.15 × combo`, capped at `3.0`.
- Combo window: `0.9 s` without a hit → combo resets to zero.
- While the combo is active, Enzo's speed drops to `45%`.
- Aura does not regenerate by itself. Only SixSeven restores it.
- Aura is spent by skills that consume it (e.g., Mogging).

## 8. Combat

### 8.1 Physical combo (Melee skill)

- Three chained hits within `0.5 s` between hits.
- Base damage: `6`, `6`, `12` (+ Strength bonus).
- Range: `34 px` in the facing direction, height `26 px`.
- The third hit applies knockback of `220 px/s`.
- No aura cost.
- If the window expires, the combo restarts at the first hit.
- Enzo can move while attacking.

### 8.2 Mogging (skill)

- Instant horizontal projectile in the facing direction.
- Cost: `25` aura.
- Damage: `20` + `2 × Aura points` + `2 × Ego points` (aura attack power).
- Speed: `620 px/s`; lifetime: `1.4 s`.
- Pierces enemies (each enemy takes damage once per projectile).
- Disappears on solid tile collision.
- Cooldown: `0.35 s` (as defined by the skill; implementation may add tick
  alignment).
- Can be used while walking, running, or in the air.
- Not enough aura: does not fire (feedback should be shown in the UI).

### 8.3 Placeholder skills

- **Nutella Shot** and **Shout** exist as skill modules/placeholders and may
  require specific equipment/tags (e.g., `NUTELLA_GUN`). Their balance and
  visuals are not final.

## 9. Enemy: Slime

- Health: `30`.
- Contact damage: `10`, with `1.0 s` of player invulnerability.
- Patrols at `60 px/s`, turns at walls and ledges.
- XP on death: `25`.
- Knockback when damaged.
- All enemies respawn when the player dies.
- No timed respawn in the MVP.

### 9.1 Common entity model

Player, Slime, and projectiles are instances of the same `Entity` with shared
base components. The implementation uses `EntityKind`/entity data plus
`Body`, `Health`, `Stats`/attributes, team/faction, controller, `Locomotion`,
and `Skills`. Creation is centralized in `EntityStore::spawn(EntitySpec)`.
Systems must not assemble entities by hand or duplicate attributes.

## 10. Progression

- XP needed for the next level: `100 × current level`.
  - Level 1 → 2: 100 XP (4 Slimes).
  - Level 2 → 3: 200 XP (8 Slimes).
- Each level-up:
  - grants `1` attribute point;
  - restores health and aura to maximum;
  - pauses simulation and opens the distribution UI.
- Starting attributes: `0` points each.
- Effect per point:

| Attribute | Effect per point |
| --- | --- |
| Speed | `+10 px/s` walk and `+6 px/s` run |
| Strength | `+2` damage to each physical combo hit |
| Health | `+10` max health (and heals `+10`) |
| Aura | `+10` max aura and `+2` aura attack damage |
| Ego | `+2` aura attack power (intelligence equivalent) |

- The level-up UI allows spending multiple points before confirming.

## 11. Health, death, and victory

- Base health: `100`; base aura: `100`.
- Contact damage can reduce health to `0` → `Dead` phase for `1.2 s`.
- Respawn at the level start with full health/aura.
- XP, level, points, and attributes are kept.
- Aura combo and projectiles are reset as appropriate.
- Falling out of the map counts as death.
- Touching the flag at the end of the level → `Victory` phase, save written, and
  overlay shown.
- `R` restarts the level while keeping progression.

## 12. Save

- **Implemented (save v2, extended compatibly):** progression save format is
  versioned (`SAVE_VERSION` 2) and includes loadout data; v1 saves are migrated
  to the default loadout. Slot storage uses `localStorage` (current
  implementation uses v2 slot keys; legacy v1 data is handled by
  migration/fallback behavior as implemented).
- Saved progression data includes level, XP, points, attributes, loadout,
  playable character identity (`Enzo`/`Valentina`), and visual customization
  profile (stable IDs). New fields use backward-compatible defaults.
- Saved on level-up, distribution confirmation, death, victory, and return to
  menu (as implemented).
- Position, enemies, and projectiles are not saved.
- Selected language is stored in `localStorage` (e.g., `enzoballz.language`) and
  restored on startup.
- Incompatible/corrupt versions should be ignored safely with a console warning
  (no crash).

## 13. HUD and UI

- Start menu with main, saves (3 slots), and options (language) screens.
- Saves screen allows starting a new game, loading, or deleting a slot; deletion
  requires confirmation.
- Fixed HUD shows health (red), aura (cyan), XP (yellow), level, points, and
  menu access. Dots open/close draggable windows: status, inventory, equipment,
  and skills. The status dot blinks when a level-up is pending.
- Windows are draggable by title, have focus/stacking and close buttons, and
  keep position during the session.
- Status window handles point distribution (`1`–`4` or click; confirm via UI
  flow).
- Control hints, phase/level-up banners, and death/victory overlays include
  restart and menu actions.
- All UI text is managed through the i18n system (pt-BR and English).

**Planned/partial:** a full action bar for all 4 slots with complete
icon/cooldown/lock/aura feedback, functional loadout editor (slot → skill,
swap/move/clear with requirement toasts), and pause-on-menu loadout editing UX.

## 14. Level

- Tile size: `32 × 32 px`.
- Initial map: `100 × 22` tiles (`3200 × 704 px`).
- Elements: continuous ground with gaps, elevated platforms, solid blocks, `6`
  Slimes, and a flag at the end.
- Camera follows Enzo with smoothing and clamps to map bounds.
- Background with gradient and simple parallax.

## 15. Sprites

- Original, pixel-art, generated by `scripts/gen-sprites.mjs`.
- Enzo: idle (2 frames), run (4), jump (1), attack (2).
- Slime: walk (2).
- Tiles: ground, block, platform.
- Flag, skill/projectile effects, and simple particles.
- Limited, consistent palette; nothing copied from existing works.

**Planned:** skill-owned assets under `assets/skills/<id>/` (`icon.png` required)
generated/wired consistently with skill definitions.

## 16. MVP success criteria (current targets)

1. The game opens in the browser via the WASM build and runs simulation at 60 Hz.
2. Enzo walks, runs with double-tap, jumps with coyote/buffer, dashes, and
   collides with tiles.
3. Alternating `6`/`7` fills aura; repeating the same key resets the combo.
4. Farming slows Enzo and makes timing/risk meaningful.
5. The 3-hit combo works and the third hit applies knockback.
6. Mogging consumes aura, hits enemies, and disappears on walls.
7. Slimes patrol, deal contact damage, and grant XP on death.
8. Level-up grants a point, pauses, and allows distribution into the four
   attributes.
9. Death respawns while keeping progression; touching the flag wins.
10. Reloading the page restores the loaded slot's progression (including loadout
    in v2 saves).
11. `cargo test -p enzo-core` covers core scenarios and passes.
12. The core does not import render/wasm/IO.
13. The start menu supports starting/loading/deleting three slots and switching
    language between pt-BR and English.
14. HUD windows open/close via dots, can be dragged/focused, and support point
    distribution by click.

## 17. Assumptions / decisions

1. **Movement/jump defaults:** `A`/`D` or arrows + `Space`/`Shift`/`J`/`K` slots;
   `W`/`↑` provides vertical intent and also triggers jump (slot 1) on press.
2. **Mogging pierces enemies** (each takes damage once) until it hits a wall.
3. **Enemies respawn only when the player dies**, not over time.
4. **Level-up pauses the game** and distribution accepts `1`–`4`/click +
   confirm.
5. **No audio in the MVP.**
6. **Balancing values** are initial and adjustable.
7. **UI in pt-BR and English**, selected in the menu and persisted locally.

## 18. Planned evolution

Items below are not fully implemented unless stated above:

1. **Persistent/configurable keybindings:** `KeyBindings` model (`InputAction`
   mapping), persistence (e.g., `enzoballz.bindings.v1`), and rebind UI.
2. **Complete loadout UX:** pause/menu editing, `LoadoutRequest`/core API flow,
   swap/move/clear, requirement/lock/cooldown/aura feedback and toasts.
3. **Skill-owned assets:** `assets/skills/<id>/{icon,entity,particles}` generated
   and loaded/rendered by skill modules; remove ad hoc shared fx ownership where
   appropriate.
4. **Mobile/touch controls:** virtual inputs emit `InputAction` directly.
5. **HTML UI over canvas:** canvas draws the world; HUD/menus/mobile controls
   move to DOM and communicate via action/loadout exports and `UiState`. HTML
   must not calculate rules or read/write saves.
6. **Finalized placeholder skills:** Nutella Shot/Shout balance, visuals, and
   gameplay integration.

See [`ACTIONS_AND_SKILLS.md`](ACTIONS_AND_SKILLS.md) for detailed contracts,
phases, and acceptance criteria.
